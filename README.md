# armb02

A native Apple Silicon (ARM64 + Metal) port of the Xbox 360 version of Call of Duty: Black Ops II, built by statically recompiling the game executable with [XenonRecomp](https://github.com/hedge-dev/XenonRecomp).

**No game data is included or ever will be.** You need your own Xbox 360 disc image, title update and DLC. The recompiled C++ output is derived from the game executable, so it is generated locally into `ppc/` and is ignored by git as well.

## Plan

1. **Repo setup and executable analysis** (in progress): extract the executable, apply the title update, run XenonAnalyse, and fill in the recompiler config.
2. **Recompile and boot to the main menu**: generate C++, then write the runtime (kernel/XAM imports, file system, XMA audio, Xenos to Metal graphics).
3. **Playable campaign from start to finish**: fix crashes mission by mission, unlock 60+ fps and add graphics settings.
4. **Later**: multiplayer, zombies, DLC and online play, including whether Plutonium interop is possible.

## Layout

| Path | What it is |
|-|-|
| `tools/XenonRecomp` | Submodule pinned to XenonRecomp `ddd128b` |
| `patches/xenonrecomp/` | Our XenonRecomp patch stack (SpeedBreaker, Deadpool, Black Ops II), applied by `scripts/apply_xenonrecomp_patches.sh` |
| `tests/` | Instruction tests for the patches (`run_instr_tests.sh`) |
| `tools/bo2scan` | Finds the addresses, jump tables and function boundaries XenonRecomp's config needs |
| `config/bo2_sp.toml` | XenonRecomp config for the campaign executable (title update v18) |
| `config/bo2_sp_switch_tables.toml` | Jump tables generated by `bo2scan` |
| `scripts/extract_game.sh` | Copies the executables and title update patches into `private/` |
| `scripts/xiso.py`, `scripts/stfs.py` | Read Xbox 360 disc images and STFS packages (title updates, DLC) |
| `runtime/` | The game's runtime (kernel and XAM, file system, Xenos GPU on Vulkan/MoltenVK, XMA audio, input, installer, settings UI), adapted from the Deadpool port, itself adapted from SpeedBreaker |
| `recomp/` | Builds the generated C++ in `ppc/` into a library for the runtime |
| `scripts/gen_import_stubs.py` | Regenerates `runtime/kernel/import_stubs.cpp`: a logging stub for every import the runtime doesn't implement yet |
| `scripts/gen_install_manifest.py` | Regenerates the installer's file list (names, sizes, SHA-256) from a disc image |
| `private/` | Your game files (git-ignored) |
| `ppc/` | Generated C++ (git-ignored) |

## Step 1 on macOS

```sh
brew install cmake ninja llvm
git clone --recursive https://github.com/MuhammadMannan/armb02.git && cd armb02
scripts/apply_xenonrecomp_patches.sh

# Build the host tools with Homebrew Clang (18 or later).
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER="$(brew --prefix llvm)/bin/clang" \
  -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++"
cmake --build build

# Copy the executables out of your ISO and the patches out of the v18 title update package.
scripts/extract_game.sh path/to/BO2.iso path/to/415608C3/000B0000/tu00000001_00000000

# Recompile the campaign executable to C++ in ppc/.
build/tools/XenonRecomp/XenonRecomp/XenonRecomp config/bo2_sp.toml tools/XenonRecomp/XenonUtils/ppc_context.h
```

The config already holds every address for title update v18. To regenerate them, for example for a different title update:

```sh
build/tools/bo2scan/bo2scan private/default.xex private/default.xexp \
  --patched private/default_patched.xex --switch-tables config/bo2_sp_switch_tables.toml
```

Then paste the printed addresses and `functions` list into `config/bo2_sp.toml`.

## Status

With the patch stack, XenonRecomp turns the v18 campaign executable into 23,918 C++ functions with no warnings: every instruction is translated and every jump table resolves. All generated files compile (checked on x86-64 Linux; arm64 still to check on your Mac). The instruction tests (486, 83 of them for Black Ops II's new instructions) pass.

One `blrl` in the C runtime's exception unwinding (around 0x82702180) is emitted as a debug trap. XenonRecomp doesn't support exceptions, and the game is not expected to reach it.

### Step 2: the runtime

`runtime/` is the Deadpool port's runtime, renamed for armb02. It applies the v18 title update to `default.xex` at load time, maps the console's `update:` device to `<game folder>/update` (the title update's patch fastfiles), and answers the game's lookups of `xam.xex` and `xboxkrnl.exe`.

On Linux (x86-64, headless) the game runs its start-up code, starts its threads, opens its fastfiles and draws its first frames. It then waits on a sound bank that isn't in place yet. Not tried on macOS yet.

```sh
# After step 1 has generated ppc/ (macOS: brew install sdl3 molten-vk vulkan-loader glslang)
cmake -B build-game -G Ninja -DCMAKE_BUILD_TYPE=Release -DARMB02_GAME=ON \
  -DCMAKE_C_COMPILER="$(brew --prefix llvm)/bin/clang" -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++"
ninja -C build-game armb02
build-game/runtime/armb02 path/to/game/default.xex   # default.xexp next to it, title update files in update/
```
